# debug.server.usbgdbstub.* is unused at the arduino-cli level. arduino-cli's
# Debug command only accepts a fixed set of server-type names (openocd,
# jlink, stutil, pyocd, bmp); a custom value here would be rejected with
# "GDB server 'usbgdbstub' is not supported". The buildprofile=usbgdbstub
# menu in boards.txt instead keeps `debug.server=openocd` and overrides
# `debug.server.openocd.path` to point at usb_gdbstub_server.exe (a real
# .exe, NOT a .cmd: cortex-debug spawns the server via Node child_process
# with no shell, and modern Node throws EINVAL on .cmd/.bat, so a .cmd would
# never run -> read ECONNRESET). The launcher parses the gdb_port cortex-debug
# assigns and spawns usb_gdbstub_bridge.ps1 on it. The bridge prints
# "Listening on port <N> for gdb connections" right after its TCP socket
# is ready, matching cortex-debug's default openocd serverReady regex,
# so cortex-debug spawns it as the debug server and then connects GDB to
# localhost:<N>. One-click Debug in Arduino IDE 2 with no separate
# "start bridge" terminal.
#
# These keys are left in place (empty) so the platform reads cleanly with
# arduino-cli's verbose debug --info even when usbgdbstub-specific lookups
# fall back here. The bridge.{describe,listports,launch}.pattern entries
# above remain available for manual command-line debugging.

debug.server.usbgdbstub.scripts_dir=
